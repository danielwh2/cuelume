# Contributing to Cuelume

Thanks for helping. Cuelume is a curated sound palette, so the bar for new
cues and themes is "would this still sound right on the hundredth play of a
working day?" — when in doubt, open an issue before a pull request.

## Setup

```sh
npm ci
npm run check   # typecheck, build, and the full test suite
```

Node 22 or newer. There are no other build steps and no runtime
dependencies to install: the library stays at zero.

## Layout

| Path | What lives there |
| --- | --- |
| `src/sounds/layers.ts` | Layer types and the builders (`knock`, `struck`, `click`, …) |
| `src/sounds/recipes.ts` | The default palette: fourteen cues, plus legacy name aliases |
| `src/sounds/{mech,bubble,press}.ts` | The same fourteen cues in other materials |
| `src/sounds/context.ts` | How a cue bends to emphasis, key, input, direction, cadence |
| `src/sounds/themes.ts` | The theme registry |
| `src/audio/output.ts` | The shared output bus, soft clip, and room |
| `src/audio/render.ts` | Turning one shaped recipe into Web Audio nodes |
| `src/audio/engine.ts` | Playback state and the public API (`play`, `press`, `release`, …) |
| `src/interactions/bind.ts` | The `data-cuelume-*` declarative bindings |
| `src/index.ts` | The public export surface — keep it small |
| `test/` | Node tests, run against `dist/` after a build |
| `scripts/sound.mjs` | Dev-only offline renderer (levels, review WAVs, plugin WAVs). Takes its layers and constants from `dist/audio/` |

`dist/` is generated by `npm run build` and never edited by hand.

## Rules that keep the palette coherent

- **Zero runtime dependencies.** Dev tooling only, and only when it earns
  its place.
- **ESM only**, strict TypeScript, no new public export without a use case
  in the README.
- **Every theme carries every cue**, arranged for all three emphases, and
  matched to the default theme by perceived level (within 1.5 dB — see
  `test/levels.test.mjs`).
- **Nothing centred above 5 kHz**, sines only for tones, and no audible
  pitch slides outside `bubble`. The tests enforce this; read them before
  tuning a cue.
- **The room and the noise are seeded**, so every page load and
  `scripts/sound.mjs` play the same ones. The room is written as 48,000
  reflections a second and placed in time, so every sample rate gets the
  same room. `ROOM_SEEDS` in `src/audio/output.ts` is the pair, out of 8,000
  candidates, that keeps every cue at every emphasis within 0.4 dB of its
  level in the average room and within 0.4 dB left to right. Changing the
  room's length, predelay or decay changes what a seed sounds like, so the
  seeds are chosen again (`test/levels.test.mjs` fails when a cue leans).
- **No limiter on the output.** A `DynamicsCompressorNode` delays everything
  by 6 ms and adds a fixed gain, 1.451 at the settings cuelume used
  (threshold -8, knee 6, ratio 12, from Chromium's makeup formula).
  `OUTPUT_GAIN` is the old 4 times that. The soft clip passes anything under
  `CLIP_KNEE` untouched; the loudest single cue, struck hardest, peaked at
  0.50 over 48 takes. `test/levels.test.mjs` fails if a cue reaches the knee.
- Behaviour-preserving refactors keep the public entries (`cuelume`,
  `cuelume/themes`) unchanged. Tests import from wherever the code lives,
  so move their imports with it and leave no re-export behind.
- A change to how a cue sounds needs a note in `CHANGELOG.md` under
  Unreleased, and the level check above re-run.

## Testing

```sh
npm test                          # build + all tests
node --test test/exports.test.mjs # just the published import surface
```

The runtime tests drive the engine through a recording Web Audio stub, so
they run in Node without a browser. If you change rendering, output, or
context shaping, one of them should fail before your fix and pass after.

One test is the exception: `test/browser.test.mjs` runs the built library
in real Chromium (via `playwright-core`, the only dev dependency besides
TypeScript) and proves the autoplay behaviour — silent before the first
interaction, sounding from it, on one shared context. It skips itself when
no browser is installed:

```sh
npx playwright-core install chromium   # once
npm run test:browser                   # required to pass, no skipping
```

## Pull requests

- One topic per PR; keep the diff reviewable.
- Say what you verified: `npm run check` output, or why a check does not
  apply.
- For a sound change, describe what changed by ear (register, brightness,
  length), not only the numbers that moved.
